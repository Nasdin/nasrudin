## Operating principles

- **Run everything end-to-end locally.** Real Docker, real cargo, real
  Lean 4. No simulations or mocks.
- **No cheating** (user feedback iter 3, see `memory/feedback_no_cheating.md`):
  an axiom is forbidden if the headline theorem of its domain appears
  as a sub-expression of the axiom. The `mass_shell_condition`
  axiom `E² − p²c² = (mc²)²` is forbidden — it contains `mc²` literally
  and pre-supposes E=mc². Mass-shell must be a *derived* theorem from
  upstream axioms (Minkowski invariant, four-momentum definition, etc.).
- **Goal is modern-physics-theorems plural** (user feedback iter 3, see
  `memory/feedback_broader_scope.md`). E=mc² is the acceptance test for
  the system, not the final destination. Don't optimize for E=mc²
  specifically; build a domain-generic combinatorics + GA system.
- **The hard-coded `DeriveRestEnergy` strategy is a Phase 0 sanity-check,
  not a result.** Phase 0.7 success means "the toolchain works", not
  "we have spontaneous derivation".
- **Diagnose root causes**, not symptoms. If a build fails, fix the cause.
  If the GA never finds a theorem, understand *why* (operator
  expressiveness, axiom availability, fitness shaping) before adding hacks.
- **Be concise** in `progress.md` updates. Sentence-level notes, not
  paragraphs. Diff-style diff/file:line references.
- **Stop the loop** if Phase 8 is complete OR if a hard external blocker
  means no progress can be made without user intervention. In the latter
  case, document the blocker in `progress.md` and *do not* schedule
  another wakeup.
